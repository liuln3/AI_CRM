# MVP 范围

> 原则：内部团队评审和套路用，模拟数据 + 真实操作并存。先把"对话式录入 + 悬浮 Agent + 看板 + 推送"这条核心闭环跑通，其他都让位。

## 做（MVP 必须有）

### 基础
- 登录 / 登出（账号密码，不做 SSO/第三方登录）
- 角色权限：管理员、销售主管、一线销售（三类）
- 模拟数据初始化：线索池、客户、跟进记录、用户

### 线索与客户
- 线索池：查看待认领线索列表、认领
- 我的客户：查看自己负责的客户列表（含客户名、联系方式、跟进状态、最后联系时间）
- 客户详情页：基础信息 + 完整沟通记录 + 跟进历史时间线
- 客户基础信息编辑（轻量手动改：名称、联系方式、跟进状态、意向度）

### 对话式 Agent 录入（核心）
- 跟进录入入口：与 Agent 对话，粘贴聊天记录 / 备注文本 / 上传会议纪要文档
- LLM 自动提取：客户姓名、联系方式、需求、意向度、跟进状态、沟通要点
- 提取结果可确认/微调后保存入库
- 保存后自动更新"最后联系时间"和跟进历史

### 数据看板（管理者）
- 客户总数
- 不同跟进状态分布（饼图/柱图）
- 本周新增客户
- 本月成交客户
- 客户状态/成交趋势图（折线）

### 全局悬浮 Agent
- 任意页面右下角悬浮入口
- 感知当前页面上下文（在哪个页面、当前对象是谁）
- 推荐相关问题（按页面动态变化）
- 点击推荐 → 以当前上下文为输入发给 Agent → 执行任务 → 返回结果
- 典型任务：客户详情页"一键生成当前客户分析报告"（状态变化、重点提醒、潜在机会、跟进建议）

### 每日推送
- 配置每日推送时间
- 推送内容：昨日新增客户、状态变化、待跟进客户、重点提醒
- 按角色定制：销售看自己的、主管看团队的
- 推送渠道：[待确认：站内消息为主，是否需要邮件/企微/飞书]

## 暂缓（MVP 不做，但预留扩展）

- 自定义客户字段配置
- 客户公海回收/重新分配规则
- 销售目标和业绩管理
- 合同 / 回款 / 发票管理
- 邮件 / 短信营销自动化
- 客户标签与分群运营
- 多团队 / 多部门组织架构（MVP 先按单团队或少量团队）
- 移动端原生 App（Web 响应式兜底）
- 数据导出（CSV/Excel）
- 操作审计日志

## 不做（明确排除）

- 复杂工作流引擎 / 审批流
- 全文知识库 / 文档管理
- 视频会议集成
- 第三方 OAuth / SSO
- 多语言 / 多币种
- 离线模式

## 成功指标（内部评审口径）

| 指标 | 定义 | 目标 | 数据来源 |
| --- | --- | --- | --- |
| 核心闭环跑通 | 认领→对话录入→看板→推送→Agent报告 五个环节均可演示 | 全部可走通 | 演示验证 |
| Agent 提取准确率 | LLM 提取的字段与人工标注一致率 | ≥ 80%（演示样本） | 抽样核对 |
| 评审可用性 | 内部评审人员能独立完成一次完整流程 | ≥ 80% 完成率 | 评审记录 |
| 模拟数据规模 | 线索/客户/跟进记录数量足以支撑看板演示 | 线索≥50、客户≥30、跟进≥100 | 初始化脚本 |
